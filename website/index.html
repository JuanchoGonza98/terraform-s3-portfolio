02 /Engineering decisions

The choices behind the code.

A focused learning project with deliberate security, maintainability, and cost tradeoffs.

01 — SECURITY↗

A public website.
A private origin.

S3 blocks public access. CloudFront reads through OAC, the bucket denies insecure transport, and SSE-S3 encrypts objects at rest. The deployment role is scoped to the existing DEV resources.

OACSSE-S3IAM
02 — REUSABILITY↗

Shared code.
Independent state.

A reusable S3 module serves DEV and HML. Each environment has its own variables and remote state key. Object uploads use for_each; a template renders environment-specific metadata. CloudFront is deployed in DEV.

03 — DELIVERY↗

Plan first.
Apply intentionally.

The manual GitHub Actions workflow checks formatting, validates the configuration, and creates a plan. An explicit input enables apply of that saved plan. OIDC supplies temporary AWS credentials.

04 /Cost awareness
~$0.10USD / month

Illustrative DEV estimate from Infracost: 0.1 GB of S3 storage, 100 write/list and 1,000 read requests, plus 10,000 CloudFront HTTPS requests and 1 GB of US-region internet transfer. Excludes HML and bootstrap resources. Actual charges vary; credits and free allowances are separate.

Deliberate scope

Small enough to explain.
Real enough to learn from.

No custom domain, WAF, customer-managed KMS key, or access-log infrastructure in this lab. These are documented tradeoffs for a public static-content portfolio, with security findings retained for review.
